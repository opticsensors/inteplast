# Correcciones de la revisión del 2026-09-15

> Este informe recoge la primera revisión de ese día. El desarrollo posterior de referencias
> externas **sí añade una migración de BD** y comprueba los dos originales del 3212; está
> documentado por separado en [ficheros-externos.md](ficheros-externos.md). Los recuentos de
> pruebas de este informe corresponden a aquella primera revisión.

Revisión de código, documentación y operación del piloto INTEPLAST. Se corrigieron los fallos
detectados sin copiar ni hidratar los ficheros del cliente. No hay cambios en las tablas de la BD;
sí cambia el contrato de acceso a ficheros y se ha regenerado el cliente TypeScript.

## Aplicación y operación

| Fallo | Comportamiento corregido |
|---|---|
| Subidas fuera del volumen persistente | El Dockerfile fija `UPLOADS_DIR=/app/uploads`, igual que el montaje de `app-uploads` |
| Tests con la BD/volúmenes de trabajo | `compose.test.yml` independiente, proyecto por ejecución, BD `app_test` y almacenamiento temporal; pytest rechaza nombres ajenos a `_test` |
| Argumentos de pytest ignorados | Los lanzadores PowerShell/Bash y el script de cobertura los pasan a pytest |
| Dockerfiles pedían un `bun.lock` inexistente | Instalación con npm y el `package-lock.json` versionado; contexto Docker excluye dependencias locales y salidas generadas |
| Refrescar notas borraba la cabecera en edición | Los campos modificados y la imagen pendiente se conservan al refrescar; solo se envían los campos de cabecera editados |
| Plegar/salir descartaba el autoguardado pendiente | Las secciones conservan sus editores; se completan guardados y subidas antes de salir; los fallos conservan el borrador |
| Un refresco sobrescribía cambios ajenos | El autoguardado escribe solo cambios locales y serializa las peticiones de cada fila |
| Registro público daba acceso al conocimiento | Desactivado por defecto; Admin crea las cuentas; rutas de aprovisionamiento exclusivas del stack de tests |
| Conocer un UUID permitía descargar ficheros | Bearer o enlace firmado de 15 minutos, limitado al fichero y a un usuario activo; un token de fichero no es un token de sesión |
| Contenido activo servido en línea | HTML/SVG y otros tipos no permitidos se descargan como adjuntos; `nosniff`, política de referencia y caché privada |
| Se ofrecía vista previa para tipos que se descargan | La selección y el arrastre de imágenes de cabecera admiten solo los formatos visibles; el visor de adjuntos aplica el mismo contrato de tipos que la API |
| `null` o referencias inexistentes terminaban en error de BD | 422 para `null` en campos no anulables; 404 para referencias de fichero inexistentes; los campos anulables siguen admitiendo `null` |
| El total de piezas era solo el tamaño de página | `count` representa todas las coincidencias antes de paginar |
| Un fallo del seed dejaba medio ejemplo | Una transacción para toda la carga, con rollback y reintento; el ejemplo existente no se modifica |
| Los tests de login esperaban texto eliminado | Selectores del dashboard actual y aprovisionamiento de usuarios adaptado al registro cerrado |
| El test de correo no abandonaba el campo | `blur()` explícito para comprobar la validación, sin depender de dónde cae un clic sobre `body` |

La base continúa siendo colaborativa para los usuarios dados de alta. Los permisos de edición
y borrado están descritos en [app-web.md](app-web.md). El registro cerrado no crea roles nuevos.
Los puertos del override de desarrollo se limitan a `127.0.0.1`.

**Actualizar instalaciones anteriores:** antes de recrear el backend, rescatar posibles bytes de
`/app/backend/uploads`. La corrección no reconstruye ficheros ya perdidos. Ver
[deployment.md](../deployment.md). El seed tampoco sustituye una copia de seguridad.

  contra el contenedor de tests, sin conectar a la BD de trabajo.

- Componentes: **15 regresiones** con los editores reales, API simulada y peticiones externas
  bloqueadas. Cubren pérdidas de borrador, concurrencia, fallos, navegación y subidas. Cerrar sesión

## Ampliación: vistas web del escaneo y del molde

Se añaden derivados GLB automáticos para STL/STEP grandes. Una cola persistente prepara
el modelo en un subproceso, limita recursos y reutiliza el resultado al volver a abrirlo.
La migración `b73c69e5fa41` añade `FilePreview`. El acceso a originales sigue pasando por
el adaptador de documentos; las descargas entregan los mismos bytes.

El molde real expone caras que OpenCascade no puede mallar directamente. Se aplican
reintentos y reparaciones sobre copias en memoria. Si quedan caras incompletas, el visor
lo indica como **Vista parcial**; más del 1 % de caras afectadas impide publicar la vista.
El recuento de caras no certifica cobertura de superficie ni de componentes. Los detalles
y parámetros están en [vistas-3d.md](vistas-3d.md).

Verificación de esta ampliación:

- **127 pruebas del backend**, con PostgreSQL y almacenamiento aislados; **91 %** de cobertura.
- **24 pruebas de componentes**, incluidos cola, reintento, aviso de vista parcial y los
  controles de PDF/3D existentes. Build de TypeScript/Vite, Biome, Ruff y mypy correctos.
- SHA-256, tamaños y fechas de los dos originales idénticos antes y después de las conversiones.
- La reducción STEP une vértices compartidos entre caras antes de simplificar. Una regresión
  geométrica comprueba que una superficie cerrada densa permanece cerrada y conserva su volumen.
- En la aplicación: escaneo **7,2 MB**, molde **16,2 MB**; giro, zoom, encuadre, reapertura y
  descarga íntegra verificados. El molde conserva aviso por **68 caras incompletas**.
- Recrear el contenedor conserva los dos GLB, sus hashes y fechas; no se repite la conversión.
  Los visores del PDF y CAD pequeño siguen pasando la comprobación con sus originales.
- Se excluyen tests y cachés de Compose Watch para evitar reinicios durante conversiones
  al modificar únicamente las pruebas. El lanzador de desarrollo conservaba `.env.local`;
  desde el 2026-09-16 esa configuración vive en `.env` y se usa `docker compose` directamente.
